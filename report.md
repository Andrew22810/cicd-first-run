# Отчёт по практической работе CI/CD

## 1. Цель работы

Изучить путь изменения от Git-коммита до результата автоматической проверки GitHub Actions: запуск тестов, сборку сайта и сохранение артефакта.

Репозиторий: https://github.com/Andrew22810/cicd-first-run

Workflow: `.github/workflows/ci.yml`

## 2. Первоначальная настройка

В собственный репозиторий были добавлены:
- `site/` — файлы учебного сайта;
- `tests/` — автоматические тесты;
- `build.py` — скрипт сборки;
- `.github/workflows/ci.yml` — workflow GitHub Actions.

Первоначальный коммит: `cf1c3bc` — `Add initial CI workflow and demo site`.

При первом запуске GitHub Actions все четыре теста прошли успешно. Сборка сайта завершилась успешно, артефакт `lesson-site` был создан и скачан. Внутри архива находились `index.html`, `style.css` и `release.json`.

## 3. Эксперимент № 1 — намеренная поломка CSS

Перед изменением был сделан прогноз: если заменить ссылку `href="style.css"` на `href="missing.css"`, тест `test_stylesheet_exists` завершится ошибкой, поскольку файл `missing.css` отсутствует.

Остальные три теста должны пройти.

Изменение было сохранено отдельным коммитом:

- Коммит: `40482d3`
- Сообщение: `Break stylesheet link to test CI`

Прогноз подтвердился. Тест `test_stylesheet_exists` завершился ошибкой:

`AssertionError: False is not true : Missing stylesheet: missing.css`

Тесты `test_heading`, `test_lesson_topic` и `test_title` прошли успешно.

Красный запуск GitHub Actions:
https://github.com/Andrew22810/cicd-first-run/actions/runs/43031518419

Поскольку шаг `Run tests` завершился с ошибкой, последующие шаги `Build site` и `Save site artifact` не выполнились. Артефакт для этого запуска не был создан.

## 4. Исправление CSS

Ссылка была возвращена к исходному значению:

`href="style.css"`

Исправление сохранено отдельным коммитом:

- Коммит: `d5769be`
- Сообщение: `Fix stylesheet link`

Локально все четыре теста прошли успешно. GitHub Actions также завершился успешно: тесты, сборка и сохранение артефакта прошли без ошибок.

Зелёный запуск после исправления:
https://github.com/Andrew22810/cicd-first-run/actions/runs/43031816924

Старый красный запуск остался в истории GitHub Actions. Это нормально: каждый запуск относится к конкретному коммиту и состоянию проекта на момент его выполнения.

## 5. Где выполнялись тесты

Локально тесты запускались в Ubuntu WSL командой:

`python3 -m unittest discover -s tests -v`

Но при отправке коммита в ветку `main` GitHub Actions автоматически запускал workflow на GitHub-hosted runner с операционной системой `ubuntu-latest`.

Поэтому результат проверки сохраняется в истории GitHub Actions и доступен в репозитории, а не только на локальном компьютере. Это позволяет увидеть, как конкретный коммит прошёл автоматическую проверку в отдельной среде CI.

## 6. Эксперимент № 2 — изменение аудитории

В отдельном коммите значение аудитории было изменено с `301` на `302`.

- Коммит: `48f7325`
- Сообщение: `Change classroom to 302`

До изменения был сделан прогноз: все четыре теста пройдут, потому что существующие проверки не контролируют номер аудитории.

Прогноз подтвердился:
- `test_heading` — OK;
- `test_lesson_topic` — OK;
- `test_stylesheet_exists` — OK;
- `test_title` — OK.

Локальная сборка также завершилась успешно. В собранном файле `dist/index.html` указана аудитория `302`.

После отправки коммита GitHub Actions завершился успешно:
- Run tests — Success;
- Build site — Success;
- Save site artifact — Success;
- общий статус — Success.

## 7. Выводы

1. GitHub Actions автоматически запускает проверки при отправке изменений в ветку `main`.
2. Тесты выполняются на GitHub-hosted runner, поэтому результат проверки доступен в истории запусков GitHub.
3. Если тест завершается ошибкой, последующие шаги workflow по умолчанию пропускаются. В нашем эксперименте из-за ошибки теста не выполнялись сборка и сохранение артефакта.
4. После исправления CSS все тесты, сборка и сохранение артефакта прошли успешно.
5. Зелёный CI не доказывает полное соответствие проекта всем требованиям. Он подтверждает только успешное выполнение существующих проверок.
6. Изменение аудитории с `301` на `302` не обнаружилось, потому что тесты не проверяют это поле. Чтобы гарантировать правильность номера аудитории, нужна отдельная автоматическая проверка.

Таким образом, автоматические тесты должны покрывать не только техническую работоспособность проекта, но и важные требования к его содержимому.
